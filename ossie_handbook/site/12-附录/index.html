    A. 词汇表（中英对照）¶

    v1.1 扩展：18 → 56 术语。涵盖核心概念、SDK、CLI、治理、生态。

    A.1 核心概念¶

    中文 英文 含义
    语义模型 Semantic Model 业务语义层描述，包含数据集、关系、度量
    语义模型文档 OSIDocument 顶层 YAML/JSON 文档，含 version + semantic_model[]
    数据集 Dataset 逻辑表（fact/dimension），对应物理表或子查询
    字段 Field 行级属性，可分组、过滤、作为度量表达式操作数
    关系 Relationship 外键连接，声明多对一
    度量 Metric 跨数据集聚合表达式
    维度 Dimension Field 的角色标记（当前仅含 is_time）
    时间维度 Time Dimension dimension.is_time: true 标记的字段
    度量上下文 from_dataset Python 端 Relationship.from 的别名（避关键字）
    时间维度判定 is_time_dimension() OSIField 方法，实现显式 > 默认规则
    方言 Dialect SQL 方言变体（7 种）
    数据类型 DataType 10 种可移植逻辑类型
    时间角色 is_time 字段作为时间维度的标记
    表达式 Expression 含 dialects[] 数组的多方言 SQL 容器
    方言表达式 DialectExpression 单个 (dialect, expression) 对
    自定义扩展 Custom Extension 厂商特定的 metadata
    AI 上下文 AI Context LLM agent 用的业务注解
    AI 上下文对象 AIContextObject 含 instructions / synonyms / examples 的结构化形态
    往返保真 Round-trip fidelity 自定义扩展在多轮转换后仍保留
    维度 vs 角色 Dimension vs Role datatype 是类型，is_time 是角色，二者独立

    A.2 本体层¶

    中文 英文 含义
    本体 Ontology 业务概念层（可选超集）
    实体类型 EntityType 真实世界对象
    值类型 ValueType 带约束的 scalar 类型
    内置类型 Built-in Types Any / Boolean / Date / DateTime / Decimal / Float / Integer / String
    多重性 Multiplicity 关系 cardinality（ManyToOne / OneToOne）
    派生概念 derived_by 基于其他数据派生 entity 人口的表达式
    派生关系 Derived Relationship 通过 derived_by 表达式计算的 relationship
    概念映射 OntologyMap 逻辑模型 → ontology 概念的桥
    链映射 LinkMapping relationship 中每个 link 的映射
    概念互操作 Conceptual Interoperability 跨模型业务概念对齐
    结构互操作 Structural Interoperability 跨工具格式互通
    标识符映射 ReferentMapping 逻辑字段绑定到 identifying relationship

    A.3 验证与 SDK¶

    中文 英文 含义
    验证器 Validator validation/validate.py
    Pydantic v2 — apache-ossie 用的类型系统
    frozen=True — 模型实例不可变
    frozen=True, extra="allow" — 向前兼容新字段
    by_alias=True — 序列化时用 from 而非 from_dataset
    exclude_none=True — 序列化时省略 None 字段
    mode="json" — 序列化严格 JSON 兼容
    populate_by_name=True — 同时接受 from 和 from_dataset
    model_config — Pydantic v2 配置项
    model_dump() — Pydantic v2 序列化方法
    model_validate() — Pydantic v2 反序列化方法
    dict[str, Any] — Pyantic schema 通用类型

    A.4 CLI / 插件¶

    中文 英文 含义
    CLI Command Line Interface ossie 命令行工具（Go）
    Cobra — GitHub 开源 CLI 框架
    插件 Plugin ~/.ossie/plugins/<name>/ 下的 converter
    Plugin Manifest plugin.yaml 描述 converter 名称、平台、invoke 命令
    Plugin Spec ossie_plugin_spec manifest schema 版本（如 0.1.0）
    Plugin Discovery — 扫描 ~/.ossie/plugins/ 找到 plugin.yaml
    IPC Inter-Process Communication 进程间通信（JSON over stdin/stdout）
    Plugin Invoker ossie-<vendor> 实际 converter 可执行文件
    OSSIE_PLUGIN_DIR — 环境变量，覆盖默认 ~/.ossie/plugins/
    Stub — 打印 "not yet implemented" 的未实现命令
    ossie plugin list — 唯一已实现的 CLI 命令

    A.5 治理 / Apache¶

    中文 英文 含义
    Apache Way — Apache 6 项价值观（meritocracy / peer-based / consensus 等）
    PPMC Podling PMC 孵化阶段项目管理委员会
    Mentor — ASF 资深成员
    IPMC Incubator PMC Apache 孵化器 PMC
    ICLA Individual CLA 个人贡献者许可协议
    CCLA Corporate CLA 企业 CLA
    Lazy Consensus — 默认通过；除非有 veto
    Binding +1 — 投票有约束力（仅 PPMC 成员）
    dev@ — 主决策邮件列表
    private@ — PPMC 私议列表
    Incubating — 孵化阶段 podling
    Squash Merge — .asf.yaml 强制 main 上只 squash merge

    A.6 生态 / 横向¶

    中文 英文 含义
    dbt SL dbt Semantic Layer dbt Labs 的语义层（Ossie 互补）
    MetricFlow — dbt Labs 开源 SQL 生成器
    Cube.dev — 自托管 SaaS 语义层
    LookML — Looker 私有 DSL
    MCP Model Context Protocol LLM 工具调用协议
    Hub-and-Spoke 中心辐射 Ossie 架构模式
    Point-to-Point 点对点 N 工具互连 = N×(N-1) 接缝
    Polar is Apache Polaris Iceberg REST catalog
    Iceberg — 列式表格式 + REST catalog
    SQLGlot — Python SQL 解析器（validator 用）
    OSIVendor — SDK 的 8 个 vendor 枚举
    OSIDialect — SDK 的 7 个方言枚举
    OSIDataType — SDK 的 10 个数据类型枚举
    OSIAIContext Union[str, AIContextObject] SDK 的 AI 上下文联合类型
    CustomExtension data: str SDK 中 data 是 JSON 字符串
    Dialect Fallback — 目标 vendor 缺 → ANSI_SQL → warn
    custom_extensions[COMMON] — 跨厂商通用的扩展命名空间
    rely.at_most_one_match — Databricks 特性 → 转 Ossie unique_keys
    One-to-Many 一对多 Wisdom ONE_TO_MANY → 反向 from/to
    Lossless / Lossy — 转换后是否保留所有信息
    STASH_VERSION — converter 用 _v: 1 标记扩展格式版本

    D. 错误消息速查¶

    v1.1 扩展：7 → 30+ 错误。组织按 [Schema]（JSON Schema）/ [Unique]（唯一性）/ [Reference]（引用）/ [SQL]（sqlglot）/ [Python SDK]（apache-ossie）/ [Converter]（每家 vendor）。

    D.1 JSON Schema 错误¶

    错误 触发条件 修复
    'semantic_model' is a required property 缺顶层字段 添加 semantic_model: [...]
    'foo' is not of type 'array' 字段是 object 而非 array 改为列表
    'foo' is not of type 'string' 字段是 number/bool 而非 string 加引号
    Additional properties are not allowed 字段不在 schema 白名单 删除或移入 custom_extensions
    minItems: 1 违反 array 为空 加至少 1 个元素
    'foo' is not one of ['String', 'Integer', ...] datatype 拼写错 查 §B.7 Enum

    D.2 唯一性错误¶

    错误 触发条件 修复
    Duplicate field name 'X' in dataset 'Y' 同 dataset 内重名字段 重命名
    Duplicate metric name 'X' 同 model 内重名 重命名
    Duplicate relationship name 'X' 同 model 内重名 重命名
    Duplicate dataset name 'X' 同 model 内重名 重命名

    D.3 引用完整性错误¶

    错误 触发条件 修复
    Relationship 'X' references unknown dataset 'Y' from/to 指向不存在 检查 dataset 名
    Metric 'X' references unknown field 'Y' 度量表达式引用字段不存在 检查字段名
    Cross-model reference not allowed Metric 跨 model 引用字段 合并 model 或用 ontology

    D.4 SQL 错误¶

    错误 触发条件 修复
    Invalid expression sqlglot 解析失败 改 SQL 或换方言
    sqlglot not installed 缺 sqlglot 依赖 pip install sqlglot
    Bare column reference in metric Metric 表达式没聚合 加 SUM/AVG/COUNT
    Aggregation in field Field 表达式用了聚合 移到 Metric
    Unknown dialect 'X' dialect 拼写错 查 §B.8 Enum
    MDX/TABLEAU/MAQL not parseable sqlglot 不支持 默认跳过

    D.5 Python SDK 错误¶

    错误 触发条件 修复
    ModuleNotFoundError: No module named 'ossie' SDK 没装 cd python && uv sync 或 PYTHONPATH=python/src
    ValidationError: from is a required property SDK signature 误用 用 from_dataset='orders'
    ValidationError: 'X' is not a valid OSIDialect enum 大小写 用 SNOWFLAKE 而非 Snowflake
    ValidationError: 'Opaque' is not a valid DataType datatype 路径错 OSIDataType.OPAQUE
    ValidationError: extra fields not permitted SDK 字段名拼错 检查 models.py
    yaml.YAMLError: did not find expected YAML 缩进错 重新格式化

    D.6 各 Converter 错误¶

    Converter 错误 修复
    Snowflake KeyError: 'SNOWFLAKE' 加 dialect: SNOWFLAKE 表达式
    Snowflake Opaque type not supported 用 vendor-specific type via custom_extensions
    dbt CUMULATIVE_SEMANTICS_LOSS Roadmap #39 待 0.2.0+
    dbt PRIVATE_METRIC_DROPPED 临时手动改 Ossie YAML
    Databricks KeyError: 'on' YAML 1.2 已用，但裸 on: 应避免
    Databricks source.* wildcard not supported 显式列出字段
    GoodData LDM date instance missing 标记 custom_extensions[GOODDATA].date_dimension: true
    Salesforce DateTime -> DateTimeTz lossy 已知转换；下游导入用 DateTimeTz
    Polaris 401 Unauthorized 加 --client-id --client-secret
    Polaris Namespace not found 先 polaris namespaces create
    Wisdom CARDINALITY_LOSS MANY_TO_MANY 待 0.2.0+
    Wisdom UNSUPPORTED_DIALECT 加 ANSI_SQL fallback
    Honeydew Metric not assigned to entity 手动指定 entity

    F. FAQ¶

    F.1 Ossie 与 dbt Semantic Layer、Cube、LookML 是什么关系？¶

    Hub-and-Spoke vs 独立产品。Ossie 是互操作规范——dbt/Cube/LookML 都可以通过 converter 接入 Ossie，反向亦然。这不替代它们，而是让它们能互相转换。

    F.2 为什么我应该用 Ossie 而不是直接写 dbt semantic_models？¶

    如果你只在一个工具栈里用，写 dbt semantic_models 即可。Ossie 的价值在于跨工具一致性——同一份模型在 Snowflake / Databricks / dbt / Tableau 都可用。

    F.3 OSSIE 还在变，0.2.0.dev0 能用吗？¶

    ⚠️ 实现状态提醒：0.2.0.dev0 是 DRAFT 版本，schema 在 0.2.0 正式发布前可能继续变更。生产环境建议锁版本号到 0.1.1（已发布稳定版）。

    F.4 CLI 的 ossie convert 怎么用？¶

    今天不能用。请直接用 vendor 自带的 CLI：

    # 等价命令
ossie-snowflake -i model.yaml -o snowflake_model.yaml
ossie-dbt osi-to-msi -i model.yaml -o semantic_manifest.json

    F.5 compliance/ 目录是空的，正常吗？¶

    正常。compliance/ 是规划中的"跨 converter 合规测试套件"。当前各 converter 的测试在各自 tests/ 目录。

    F.6 本体层（ontology）必须用吗？¶

    不必。TPC-DS 示例就是纯结构模型，没有 ontology。本体层是给"跨模型业务概念对齐"这种高级场景准备的。

    F.7 怎么给 Ossie 提反馈？¶

    1. 小问题：去 GitHub Issues
    2. 想法/讨论：去 GitHub Discussions
    3. 实质贡献：在 dev-subscribe@ossie.apache.org 订阅邮件列表，发起讨论

    J. 手册维护指南¶

    v1.2 新增。面向贡献者：如何修改、发布、校对。

    J.1 贡献流程¶

    1. fork + branch：从 apache/ossie main 创建 handbook-<topic> 分支
    2. 本地编辑：在 handbook/src/*.md 直接修改；按 v1.1 模式加英文 Abstract + 三类读者 callout + 章末 cheat-sheet
    3. 本地构建：mkdocs build --strict 必须 0 警告
    4. PR：标题 handbook: <一句话描述>；body 列出修改章节 + 关键校验结果
    5. review：≥1 PMC member +1（Apache Way）；spec 字段变更需 ≥3 binding +1（见 §11.3）
    6. merge：squash merge only（.asf.yaml 限定）；commit message 用 handbook: vX.Y <一句话>

    参考 CONTRIBUTING.md:1-287（仓库根目录）。

    J.2 校对 checklist（提交前自检）¶

    • [ ] path:line 引用：每个 file:line 引用必须实际存在于当前仓库。可用： 
      sed -n 'L,p' core-spec/osi-schema.json  # 验证 schema 引用
sed -n 'L,p' python/src/ossie/models.py  # 验证 SDK 引用
    • [ ] mkdocs build --strict：0 警告（包含 broken link、missing file、unused variable）
    • [ ] 英文 Abstract：每章 ≤200 字；摘要与正文一致
    • [ ] 三类读者侧栏：每章顶部必有【为用户】【为开发者】【为架构师】
    • [ ] 章末 cheat-sheet：每章末尾必须有 "X.X 📌 章节要点速查" 表
    • [ ] 诚实标注：Go CLI stub / compliance 占位 / ontology block 等"已知未做"项在 README、00-序章、对应章节均提及
    • [ ] PDF 同步：若新增/删除章节，运行 python3 build_pdf.py 重生成 PDF
