# 00.5. 财务入门 — 给非财务背景的读者

> **本节定位** [用户向] — 如果你**完全不懂财报、估值、投行、PE** 这套语言,这一章就是为你写的。它是 handbook 的"零基础桥梁" — 读完这一章,你后续章节里遇到的 FSI 术语 90% 都不会卡住。如果你本身已经是 banker / analyst / PM,这一章可以直接跳过。

## TL;DR

- 任何一家公司,**三个数字**告诉你它的全貌:**资产** 多少(BS)、**赚了多少**(IS)、**收了多少钱**(CF)。
- 想"公司值多少钱"?三种主要方法:**DCF**(未来现金流折现)、**comps**(同行对比)、**precedents**(类似交易对比)。三种画在一起就是 **football field**。
- 评估公司的人分六大角色:**投行 (IB)** 帮卖、**股权研究 (ER)** 评上市公司、**PE** 用自己的钱买、**财富管理 (WM)** 给富人管钱、**基金会计 (Fund Admin)** 给基金记账、**运营 (Operations)** 做 KYC/合规。
- 投行的产物:**CIM**(卖公司的"卖书")、**teaser**(匿名一页)、**pitch deck**(品牌化 PPT)、**merger model**(并购 Excel)、**process letter**(买方投标指引)、**deal tracker**(全流程跟踪)。
- PE 的产物:**IC memo**(投决会 9 段备忘)、**DD checklist**(尽调清单)、**LBO 模型**(借钱买公司)、**LP statement**(季度对账单)、**capital account**(出资+损益余额)。
- 收益衡量:IRR(年化)、MOIC(总倍数)、TVPI/DPI/RVPI(基金全生命周期)、AUM(管理资产规模)。
- 会计核心动作:**reconciliation**(对账)、**break**(差异)、**tie-out**(对到一致)、**accrual**(计提)、**roll-forward**(滚转)、**variance commentary**(差异说明)。

**给完全不懂财务的读者**:如果你读完 TL;DR 还是一头雾水,跳到 §1.1 的"公司 = 把资本变成利润的机器"开始。每个概念都有生活类比。如果你只是不熟悉 FSI 术语但懂基础会计,直接从 §3(角色地图)开始。

## What you'll learn

读完这一章,你应该能:

- 说出 **BS / IS / CF** 三大表各自回答什么
- 说出 **DCF / comps / precedents** 三种估值法的核心思路
- 区分**卖方**(投行 / 股权研究)和**买方**(PE / WM)
- 知道 **CIM / IC memo / LBO / IRR / MOIC** 是什么
- 读懂后续章节里出现的 **EBITDA / EV / NAV / GP / LP / AUM / carry** 等术语
- 知道 **KYC / NAV package / LP statement / GL recon / tie-out** 是基金会计/运营做什么

## 1. 公司是什么 — 财报三表 + 关键术语

### 1.1 公司:一个把资本变成利润的机器

最朴素的视角:**公司 = 把钱(资本)变成更多钱(利润)的机器**。要理解这台机器怎么运转,你只需要看三张表:

- **资产负债表 (Balance Sheet, BS)** — 某一天它"有什么、欠什么"
- **利润表 (Income Statement, IS)** — 一段时间它"赚了多少、花了多少"
- **现金流表 (Cash Flow, CF)** — 一段时间钱"实际进出了多少"

这三张表是任何分析(无论 IB pitch、股权研究、PE DD、基金会计)的**共同语言**。

**类比**:把公司想象成一家水果店。BS 是"今天下午 5 点店里有多少存货、多少现金、多少欠款",IS 是"今天从早到晚卖了多少水果、付了多少房租",CF 是"今天实际收了多少现金、实际付了多少现金"。会计上利润和现金是两回事 — 卖出 1000 元水果,可能只收到 500 元现金(顾客赊账),但账上记 1000 元收入。

### 1.2 资产负债表 BS(Balance Sheet)

回答一个时点问题:**这一刻,公司有什么、欠什么?**

```text
                    资产负债表(BS) — 示例:某 SaaS 公司,2025-12-31
+----------------------------+----------------------------+
| 资产(Assets)              | 负债 + 所有者权益           |
+----------------------------+----------------------------+
| 现金              50M     | 应付账款             8M    |
| 应收账款(AR)      30M     | 短期借款            10M    |
| 存货               5M     | 流动负债合计         18M    |
| 其他流动资产       5M     | 长期借款             25M    |
| 流动资产合计      90M     | 负债合计             43M    |
| 固定资产(PP&E)    15M     | 股东资本             20M    |
| 无形资产           8M     | 留存收益             50M    |
| 非流动资产合计    23M     | 所有者权益合计        70M    |
+----------------------------+----------------------------+
| 资产合计          113M    | 负债+权益合计        113M   |
+----------------------------+----------------------------+
```

**核心公式**(任何财务分析都从这里开始):

```text
资产 = 负债 + 所有者权益
```

在这个例子里:**113M = 43M + 70M**。这意味着每 1 元资产,要么是借来的(负债),要么是股东投的/赚的(权益)。永远不会"凭空出现"。

### 1.3 利润表 IS(Income Statement)

回答一段时间问题:**这段时间,公司赚了多少?**

```text
                    利润表(IS) — 示例:某 SaaS 公司,2025 全年
+----------------------------------+
| 营业收入 (Revenue)          100M |
| - 营业成本 (COGS)            25M |
| = 毛利润 (Gross Profit)      75M |  (毛利率 75%)
| - 销售费用 (S&M)             30M |
| - 管理费用 (G&A)              8M |
| - 研发费用 (R&D)             15M |
| - 折旧与摊销 (D&A)            5M |
| = 营业利润 (Operating)       17M |  (营业利润率 17%)
| - 利息费用                    2M |
| - 所得税                      3M |
| = 净利润 (Net Income)        12M |  (净利率 12%)
+----------------------------------+
```

**几个关键比率**(handbook 后续章节会大量出现):

- **毛利率 (Gross Margin)** = 毛利润 / 营收(衡量产品本身赚不赚钱)。SaaS 通常 70-80%(卖软件),零售通常 20-30%(卖实物)。**例:75M / 100M = 75%**。
- **营业利润率 (Operating Margin)** = 营业利润 / 营收(衡量经营管理效率)。**例:17M / 100M = 17%**。
- **EBIT (Earnings Before Interest and Tax)** = 营业利润 = 17M(本例)。
- **EBITDA (Earnings Before Interest, Tax, Depreciation, Amortization)** = EBIT + D&A = 17M + 5M = **22M**。IB/PE 估值最爱用的指标(因为它最接近"经营性现金流")。详细在 §1.5。
- **净利润 (Net Income, NI)** = 12M。最终归属于股东的利润。股权估值的核心。

**类比**:利润表像水果店一年的流水账。营收 1000 万不代表老板口袋里多了 1000 万 — 还要扣掉进货成本、员工工资、店铺房租、贷款利息、税。**净利润** 才是真正能分给股东/再投资的钱。

### 1.4 现金流表 CF(Cash Flow)

回答一段时间问题:**钱实际进出了多少?**

```text
                    现金流表(CF)
+--------------------------------------+
| 经营活动现金流 (CFO)                |
|    = 客户实际收到现金 - 实际付的成本  |
|                                      |
| 投资活动现金流 (CFI)                |
|    = 卖设备 - 买设备 / 收利息 - 投    |
|                                      |
| 筹资活动现金流 (CFF)                |
|    = 借款 - 还债 / 股东注资 - 分红    |
|                                      |
| 期末现金变动 = CFO + CFI + CFF       |
+--------------------------------------+
```

**为什么 CF 与 IS 不同?**

- 利润表按"权责发生制"记:卖出 1000 万水果(无论是否收到现金)就记 1000 万收入。
- 现金流按"收付实现制"记:只有现金真的进出才算。
- **公司可以长期盈利却破产**:利润表显示赚钱,但客户一直赊账,现金从没进来。

**FCF (Free Cash Flow / 自由现金流)** — 这是 DCF 的核心输入:

```text
FCF = 经营活动现金流(CFO) - 资本开支(CapEx)
```

**CapEx (Capital Expenditure)** 是公司花在固定资产(机器、厂房、办公桌)上的钱。

**类比**:FCF 像水果店的"老板可以自由支配的钱"。交完房租、发完工资、买完新的货架、还完贷款利息之后,剩下的钱才是 FCF。FCF 决定公司能不能给股东分红、回购股票、做新投资。

### 1.5 关键比率:margin / EBITDA / FCF / CapEx / working capital

handbook 后续章节(尤其是 §5-verticals 和 §6-agents)反复提到以下比率,提前理解:

- **EBITDA**:在 EBIT 基础上加回折旧 (D) 与摊销 (A)。折旧是过去买设备的会计费用,摊销是买无形资产的会计费用 — 它们**不是当期现金支出**,所以加回来更能反映"真实的现金流生成能力"。这是 IB 估值、PE LBO 模型最常用的盈利能力指标。

- **FCF margin** = FCF / 营收 — 衡量"营收里有多少变成可自由分配的现金"。

- **CapEx** = 资本开支。重型制造/电信/半导体 CapEx 高(因为要建厂买设备);SaaS / 咨询 / 软件服务 CapEx 低(轻资产)。这直接影响估值倍数。

- **Working Capital(营运资本)** = 流动资产 - 流动负债。代表"日常运营需要的钱"。
  - 应收账款太多 = 客户欠钱不还 → working capital 涨 → 占压现金
  - 应付账款多 = 拖供应商款 → 占便宜 → working capital 降

- **SaaS 专属指标**(股权研究章节会大量出现):
  - **ARR (Annual Recurring Revenue)** — 年度经常性收入。订阅业务(SaaS、流媒体、SaaS-like)用 ARR 衡量规模,而不是一次性合同金额。
  - **NRR (Net Revenue Retention)** — 净收入留存率。考虑流失+扩张后,老客户群的收入同比变化。NRR > 100% 意味着即使不卖新客户,老客户群也在增长(健康的 SaaS 公司)。
  - **Rule of 40** — SaaS 健康度经验法则:**营收增长率 % + 利润率 % ≥ 40%** 视为可持续。

| 术语 | 中文 | 一句话解释 |

## 2. 公司怎么估值 — 估值的逻辑与方法

### 2.1 为什么估值? — 买卖双方的博弈

估值只有一个问题:**这家公司值多少钱?**

但答案是"看情况":
- 卖方(原股东):想卖高
- 买方(新股东):想买低
- 中间人(投行 / 分析师):提供"公允价格"参考

所有估值方法本质上都是回答:**"基于某种假设,这家公司应该值 X"**。不同方法的假设不同,得出不同结果。投行最终会把所有结果画在一张图上(football field,见 §2.3),告诉客户"市场认为你的公司值 80-120 亿"。

### 2.2 三种主要估值方法

#### 2.2.1 DCF(Discounted Cash Flow / 现金流折现)

**核心思想**:公司未来 N 年能赚的现金流 + 终值,按折现率还原成今天的价值。

```text
DCF 估值 = Σ(FCF_t / (1+r)^t) + Terminal Value / (1+r)^N
            └─────── 预测期(N 通常 5-10 年) ──────┘   └─ 终值 ─┘
            r = 折现率(常用 WACC)
```

**关键输入**:
- **FCF**(§1.4)— 公司未来每年能产生多少自由现金流
- **WACC (Weighted Average Cost of Capital / 加权平均资本成本)** — 公司借债成本 + 股权成本的加权平均。DCF 用的"折现率"
- **Terminal Value (终值)** — 预测期结束后的剩余价值(假设公司永续经营)。**通常占 DCF 总值 50% 以上**,所以假设很敏感。
- **Sensitivity Table (敏感性表)** — 改变 WACC / 增长率 / 终值倍数,看估值如何变化(估值不是单点,是范围)

**类比**:DCF 像预测果树未来 10 年每年结多少果,按"今年果子比明年值钱的折现率"折回今天。如果果树寿命 30 年,还要预测第 11-30 年的果子(终值)。

**对应 handbook**:DCF 详细模型在 `08-skills.md` 的 `dcf-model` skill 段、`09-cookbooks.md` 的 cookbook 部署。

#### 2.2.2 Comps(Trading Comps / 可比公司分析)

**核心思想**:选 5-10 家**上市同行**,看他们市场交易时按多少倍利润/收入卖。把倍数套用到目标公司,得到估值区间。

```text
Comps 估值 = 目标公司利润/收入 × 同行平均倍数
            └──────── EV/EBITDA / EV/Revenue / P/E ────────┘
```

**最常用倍数**:
- **EV / EBITDA**:企业价值 / EBITDA(§1.5) — 跨资本结构可比
- **EV / Revenue**:适合未盈利公司(SaaS、生物科技)
- **P / E (Price / Earnings)**:股价 / 每股利润 — 股票视角

**Comps 表格关键列**:Ticker / Market Cap / EV / Revenue / EBITDA / EBITDA Margin / EV/Revenue / EV/EBITDA,然后给 25/50/75 分位 + 中位。

**类比**:comps 像看"隔壁小区三室一厅都卖了 500 万",所以你家三室一厅也值 500 万左右。

**对应 handbook**:`08-skills.md` 的 `comps-analysis` skill(`trading multiples + 25/50/75 统计`)。

#### 2.2.3 Precedents / Transaction Comps(可比交易)

**核心思想**:选 3-5 起**近期完成的类似并购案**,看买方付了多少倍 EBITDA / Revenue。这给出的是"控制权溢价"(并购通常比二级市场贵 20-40%)。

**类比**:precedents 像"上个月隔壁那栋楼被一个公司买下来付了 500 万",所以你这个三室一厅如果卖给公司,可能值 600 万(因为公司买来经营能赚更多)。

**区别于 Trading Comps**:trading comps 反映"散户在公开市场愿意付多少",precedents 反映"产业买家愿意付多少"。卖方公司卖身时通常用 precedents(因为有买家竞争)。

**对应 handbook**:handbook 中 comps-analysis skill 同时覆盖 trading comps 与 precedents。

### 2.3 Football Field(估值区间图)

**核心思想**:把多种估值方法(DCF / comps / precedents / LBO / 52-week range)的**结果区间**画在一张横轴图上,看重叠区间。

```text
估值方法                  80  90  100  110  120  130  140 (per share)
                    +-----+---+----+----+----+----+----+
DCF (WACC 8-12%)    |        ████        |       |
DCF (g 1-3%)        |              █████ |       |
Trading Comps       |    ████████████     |       |
Precedents          |              ████████████   |
LBO (Sponsor case)  |    ████████████  |       |
52-week range       |████████████████████|       |
                    +-----+---+----+----+----+----+----+
最终推荐区间:                  └──────┘
                              90-115
```

**类比**:football field 像看"四个分析师给房子估了价,区间分别是 80-100、90-110、100-120、95-130",你选重叠最多的区间(95-110)作为"市场公允价值"。

**对应 handbook**:pitch-agent 和 model-builder 默认输出 football field。

### 2.4 估值关键术语

- **EV (Enterprise Value / 企业价值)** = 股权市值 + 净负债。**买入整家公司(股权+债权)所需的代价**。比 market cap 更全面,因为买公司还要还债。
- **Equity Value (股权价值)** = market cap = 股价 × 总股本。只算股东拿到的部分。
- **Multiple (估值倍数)** = 价格 / 业绩指标(EV/EBITDA、P/E 等)。倍数越高,市场对公司预期越好。
- **Beta (β / 贝塔系数)** = 个股相对市场的波动性。B=1 与市场同波动,B>1 比市场更波动,B<1 比市场更稳。CAPM(资本资产定价模型)用 Beta 算股权成本。
- **WACC / Discount Rate** — §2.2.1 已述。
- **Synergies (协同效应)** — 并购后双方整合预期产生的额外收入或成本节约。
- **Accretion / Dilution (增值 / 稀释)** — 并购后每股盈余(EPS)比交易前**增加**(增值)还是**减少**(稀释)。
- **PPA (Purchase Price Allocation / 购买价格分摊)** — 把收购对价分摊到有形/无形资产与商誉的会计过程。
- **Pro Forma EPS** — 假设并购已完成的备考每股收益,用于看 accretion/dilution。

| Pro Forma EPS | 备考每股收益 |

### 2.6 估值的常见陷阱 — 给非分析师的提醒

估值听起来科学,实际**高度依赖假设**。下面这些陷阱是 handbook 后续章节会反复提醒你的:

- **"Garbage In, Garbage Out"** — DCF 的所有数字都来自假设(WACC、增长率、终值倍数)。改一个数字,估值可能差 50%。任何 DCF 都要看 sensitivity table,**永远别只看单点估值**。
- **Multiple Compression / Expansion** — 整个行业的市场倍数会随周期波动。2021 年 SaaS 公司普遍 20x+ revenue,2023 年降到 8x。同一家公司,multiple 不同估值差 2-3 倍。
- **Terminal Value 占 DCF 一半以上** — 预测期外的"永续"假设是估值最大变量。"永续增长率 2% vs 4%"可以让 DCF 差 30%。
- **Comps 的"可比"定义** — 严格意义上的可比 = 业务模式 + 规模 + 增长率 + 利润率都相近。一家 100x ARR 的 SaaS 与一家 10x ARR 的 SaaS,即使同行业,**不能直接套倍数**。
- **LBO 模型的"幻觉"** — LBO 算出来的 IRR/MOIC 是高度乐观的(假设 exit multiple 维持、EBITDA 持续增长、按时退出)。**实际 PE 失败案例常见**。
- **Precedents 难以找到完全相同的** — 真正可比的历史交易很少,实务中常用"宽松可比"(相近行业、不同规模、不同年份)。

**给读者的提醒**:看到任何"估值 $X"或"目标价 $Y"的输出,都要问一句"假设是什么?"。handbook 后续章节(comps-analysis / dcf-model / pitch-agent)都会强调 sensitivity 与 scenario。

### 3.2 投行 IB (Investment Banking)

**做什么**:帮**客户公司**做两件事 — **卖**(卖方并购顾问)或**买**(买方并购顾问)。

- **卖方案例**:A 公司想卖给 B 公司,A 公司雇 Goldman / Morgan Stanley 做顾问,负责找买家、定价、谈条款。
- **买方案例**:B 公司想收购 A 公司,B 公司雇 JPMorgan 做顾问,负责报价、DD(尽调)、融资。

**典型产物**:CIM / teaser / pitch deck / merger model / process letter / deal tracker(§4 详解)。

**对应 handbook**:`investment-banking` vertical + `pitch-agent` / `model-builder` 两个 agent。

### 3.3 股权研究 ER (Equity Research)

**做什么**:为**机构投资者**(对冲基金、共同基金)研究**已上市公司**的股票,发布 **Buy / Hold / Sell** 评级与目标价。

- 典型产物:earnings note / initiating coverage / model update / thesis tracker / sector overview / tearsheet。
- 立场:不是"卖方 IB"那种"撮合交易赚钱",而是"读者订阅研究报告赚钱"。
- 不直接交易,但研究质量直接影响机构的买卖决策。

**对应 handbook**:`equity-research` vertical + `earnings-reviewer` / `market-researcher` / `meeting-prep-agent` 三个 agent。

### 3.4 私募 PE (Private Equity)

**做什么**:**用自己的钱(或 LP 的钱)买下整家公司**,靠改善经营、扩张、重组,5-7 年后高价卖出获利。

- 与 IB 区别:IB 是"帮人买卖",PE 是"自己买卖"。
- 经典结构:**LBO**(借钱买公司,见 §5.5)。
- 典型产物:IC memo / DD checklist / LBO model / LP statement / NAV package。

**对应 handbook**:`private-equity` vertical + `valuation-reviewer` agent。

### 3.5 财富管理 WM (Wealth Management)

**做什么**:**给高净值客户**管钱,做资产配置 / 财务规划 / 客户沟通。

- 与 PE 区别:WM 管的是**个人资产**(组合配置:股 + 债 + 现金 + 房产),PE 管的是**基金**(投资到非上市企业)。
- 典型产物:client review / financial plan / rebalance proposal / tax-loss harvesting。

**对应 handbook**:`wealth-management` vertical + `meeting-prep-agent` agent。

### 3.6 基金会计 Fund Admin

**做什么**:给**基金**(PE fund / hedge fund / mutual fund)**记账、估值、出报表**。角色是"基金的会计部门"。

- 不投资、不研究,只确保数字准确。
- 典型产物:GL reconciliation / NAV package / LP statement / capital account / accrual schedule。

**对应 handbook**:`fund-admin` vertical + `gl-reconciler` / `month-end-closer` / `statement-auditor` 三个 agent。

### 3.7 运营 Operations

**做什么**:**KYC / AML / 合规审查 / 客户开户**等"非交易"但合规必需的工作。

- 客户来开户,要核实身份、资金来源、是否在制裁名单。
- 典型产物:KYC screening report / risk score / escalation memo。

**对应 handbook**:`operations` vertical + `kyc-screener` agent。

**对应 handbook**:`03-marketplace-catalog.md` 有每个 vertical 的功能定义,`06-agents.md` 有每个 agent 的子任务分解。

## 4. 投行卖方做什么 — IB 工作流(深度)

投行一项核心任务:**"卖公司"**。完整流程覆盖从拿到 mandate(委托)到 close(交割)的几个月到一年。

### 4.1 CIM(Confidential Information Memorandum)— 卖公司的"卖书"

**Confidential Information Memorandum(保密信息备忘录)** — 卖方给潜在买家披露公司详细信息的"卖书"。通常 30-80 页,包括公司介绍 / 行业分析 / 财务摘要 / 增长机会 / 风险因素。

**保密**:CIM 里有公司敏感数据(客户名单、毛利、未公开预测),所以**签 NDA**(保密协议)后才给。

**类比**:CIM 像你卖房子时给意向买家的"房屋说明书" — 户型、面积、邻居、装修、缺点都有,但只有签了保密协议的"严肃买家"才给。

**对应 handbook**:`investment-banking` vertical 下的 `cim-builder` skill。

### 4.2 Teaser — 吸引买家眼球的"一页纸"

**Teaser(匿名一页简介)** — 在签 NDA 之前的"匿名 hook"。只描述**行业与体量**(例如"北美工业自动化公司,EBITDA $50-100M"),**不透露公司名**,让买家"感兴趣但没信息"。

**类比**:teaser 像你房子要卖时,在中介橱窗贴的"市中心三室一厅,首付 80 万起,户型图私聊"。

### 4.3 Buyer List — 谁可能买

**Buyer List(买方清单)** — 卖方 process 中按类型分类的潜在买家:
- **战略买家 (Strategic)**:同行业的公司(如果 A 公司被同行业的 B 公司收购,叫 horizontal M&A)
- **财务买家 (Financial)**:PE 基金
- **混合**:少数战略 + 多数 PE

**类比**:buyer list 像你卖房子时,中介心里记的"可能买这个小区的人" — 改善型家庭、年轻白领、投资客。

### 4.4 Pitch Deck / Pitch Book — 说服客户的演示文稿

**Pitch Deck(路演册)** — 投行**主动**给潜在客户的品牌化 PPT,目的是**赢 mandate**(让客户雇你做顾问)。

- 不是为了某个具体交易,而是"为什么你应该选我们做顾问"的销售材料。
- 通常 20-30 页,包含团队 / 案例 / 市场观点 / 收费结构。

**Pitch Book(更具体的版本)** — 围绕**某个具体交易**的演示材料(可能用于 buyer meeting / IC discussion)。

**对应 handbook**:`pitch-deck` skill,`pitch-agent` agent 默认填充银行 PPT 模板。

### 4.5 Merger Model — 两家合并后值多少

**Merger Model(并购模型)** — Excel 模型,预测**两家假设合并**后的:
- 协同效应(Synergies,§2.4):收入 +X 亿、成本 -Y 亿
- 增值 / 稀释(Accretion / Dilution):合并后 EPS 比合并前高还是低
- PPA(购买价格分摊,§2.4):把收购对价分到资产/商誉
- Pro Forma EPS(§2.4):备考每股收益

**类比**:merger model 像婚前算账 — 两家合并后,家庭总收入多少、每月开销多少、扣完税剩多少、每人分多少。

**对应 handbook**:`merger-model` skill。

### 4.6 Process Letter / IOI — 正式流程

**Process Letter(流程信)** — 卖方给买方的**正式投标指引**:第一轮 IOI(意向报价)、第二轮 Final Bid(正式报价)、管理层演示时间表、所需文件清单。

**IOI (Indication of Interest / 意向报价)** — 买方在第一轮提交的**非约束性**估值意向("我们感兴趣,大约 95-105 亿")。非约束 = 即使后续不做也不违约。

**Final Bid / Binding Bid** — 第二轮的**约束性报价**,正式、有法律约束力。

**类比**:process letter 像你卖房时中介发给买家的"竞标规则" — 第一轮 9 月 1 日前提交意向,第二轮 9 月 15 日前提交正式报价,9 月 20 日前签约。

### 4.7 Deal Tracker — 全流程跟踪

**Deal Tracker(交易跟踪表)** — 跟踪在执行交易的里程碑、deadline、action items 的列表。一行一个 deal 或一个 workstream。

### 4.8 IB 工作流速查表

| 术语 | 中文 | 一句话 |

| Teaser | 匿名一页简介 | 吸引买家的"匿名 hook" |

## 5. 买方怎么投 — PE/VC 工作流(深度)

### 5.1 PE 基金的"钱" — capital call / distribution / AUM

**PE 基金不是一个账户,而是一段"钱进钱出"的生命周期**:

```text
        LP 承诺出资 $1B (例如分 5 年投完)
              ↓
   GP 发 capital call → LP 实际打钱 $50M / 次
              ↓
   GP 用这些钱投资 / 持有 / 改善公司
              ↓
   GP 把退出收益以 distribution 形式返还 LP
              ↓
   基金到期 → 清算
```

**关键术语**:
- **AUM (Assets Under Management / 管理资产规模)** — 资管机构正在管理的资产总市值。**衡量公司规模的核心指标**。
- **Capital Call (出资通知)** — GP 要求 LP 在指定日期投入承诺资本的通知。"你承诺了 1 亿,先打 1000 万"。
- **Distribution (收益分配)** — GP 把退出收益返还给 LP 的付款。

### 5.2 GP / LP / Management Fee / Carried Interest

**PE 基金的双元结构**:

```text
  LP(Limited Partner,有限合伙人)
    ↓ 出资 + 不参与管理
    ↓ 享受收益(被动)
    ↓
  GP(General Partner,普通合伙人)
    ↑ 收管理费 + 业绩分成
    ↑ 负责投资决策 + 日常管理(主动)
```

**GP 的两类收入**:

1. **Management Fee(管理费)** — GP 每年按承诺/已投资本金向 LP 收取的费用(通常 **1.5-2% / 年**)。无论赚不赚钱都要给。这是 GP 的"固定工资"。
2. **Carried Interest (carry / 业绩分成)** — GP 在 LP 收益超过 hurdle 后获得的**超额利润分成**(通常 **20%**)。这是 GP 的"业绩奖金"。

### 5.3 收益衡量:IRR / MOIC / TVPI / DPI / RVPI

PE 业绩衡量**多套指标**,各有用途:

| 指标 | 含义 | 用途 |
|---|---|---|
| **IRR (Internal Rate of Return / 内部收益率)** | 年化复合回报率 | 衡量年化表现 |
| **MOIC (Multiple on Invested Capital / 投资倍数)** | 总退出价值 / 总投入 | 衡量总倍数(非年化) |
| **TVPI (Total Value to Paid-In)** | (已分配 + 未分配) / 总投入 | 基金"理论"总回报 |
| **DPI (Distributions to Paid-In)** | 已分配现金 / 总投入 | 基金"实际到手"现金 |
| **RVPI (Residual Value to Paid-In)** | 未分配(剩余估值) / 总投入 | 纸面上未实现的部分 |

**类比**:你买了一套房 100 万,5 年后卖了 200 万,但还有 50 万租金收入没到账。
- MOIC = 250/100 = 2.5x
- IRR ≈ 20%(年化)
- TVPI = 250/100 = 2.5x
- DPI = 200/100 = 2.0x(只算到手现金)
- RVPI = 50/100 = 0.5x(未到手)

### 5.4 投资流程:sourcing → screen → DD → IC memo → close → portfolio → exit

```text
sourcing      → deal sourcing(项目源开发)
                  PE 通过研究、cold outreach、行业会议主动找项目
                ↓
screening     → screen(立项初筛)
                  拿到 CIM/teaser 后快速判断 pass / fail(行业 / 规模 / 估值)
                ↓
DD            → due diligence(尽职调查)
                  财务 / 法律 / 商业 / 运营的全面核查
                ↓
IC memo       → investment committee memo(投决会备忘)
                  9 段结构: exec sum → investment thesis → market → financial →
                            DD findings → valuation → structure → risks → recommendation
                ↓
IC vote       → investment committee(投决会)
                  合伙人级别决策机构,投 vs 不投
                ↓
close         → 签约 + 交割 + 资金到位
                ↓
portfolio     → 持有期间的价值创造(运营改善 / 扩张 / 收购 / 重组)
                ↓
exit          → 退出:IPO / 卖给战略买家 / 卖给其他 PE / 管理层回购
```

### 5.5 LBO(Leveraged Buyout / 杠杆收购)— PE 经典结构

**核心思想**:**用大量债务融资买公司**,靠经营现金流还债,5-7 年后用更高估值卖出。

**为什么借钱买?**因为:
- 自己出 30%,借 70% → 用 30% 撬动 100% 的资产
- 公司现金流先还债,还完的归股东
- 即使公司只增值 2 倍,股东回报是 6-7 倍(因为杠杆放大)

**LBO 模型的关键表**:

| 表 | 作用 |
|---|---|
| **Sources & Uses (资金来源与用途)** | 融资端(银行贷款 + 高收益债 + 股权)与对价端(收购价 + 手续费)的平衡表 |
| **Debt Schedule (债务时间表)** | 逐年逐笔计算债务本金、利息、还款 |
| **Operating Model** | 5-7 年的收入/EBITDA/FCF 预测 |
| **Returns Sensitivity** | 改变 entry/leverage/exit/growth/hold 后看 IRR/MOIC |
| **EBITDA Bridge** | 把 EBITDA 从收购时点到退出时点的变化分解为驱动项(organic growth + margin expansion + M&A) |

**类比**:LBO 像贷款买房 — 你出 30% 首付,银行借 70%。如果房价 5 年涨 50%,你的 30% 实际回报是 (1.5 - 0.3) / 0.3 = 4 倍,杠杆放大了回报。但房价跌的话,亏得也更快。

**对应 handbook**:`private-equity` vertical + `lbo-model` skill。

#### 5.5.1 LBO 数字算例(便于直观理解)

假设 PE 基金收购一家年 EBITDA $100M 的工业公司,5 年后卖出:

```text
收购时点 (Year 0):
  Enterprise Value = 100M EBITDA x 8x multiple = 800M EV
  融资:
    银行贷款 (senior debt, 5x EBITDA)  = 500M  (62.5%)
    高收益债 (subordinated, 1x EBITDA) = 100M  (12.5%)
    PE 股权 (sponsor equity)            = 200M  (25.0%)
  Sources 合计                          = 800M
  Uses (收购对价 + 手续费)              = 800M

持有 5 年 (Year 1-5):
  EBITDA 增长: 100 -> 150  (8.5% CAGR + margin expansion)
  每年用 FCF 还债: 500M -> 250M (银行贷款还一半)
  高收益债: 维持 100M (不强制还)

退出 (Year 5):
  Exit EV = 150M EBITDA x 10x multiple = 1500M
  减剩余债务: 250M (银行贷款) + 100M (高收益债) = 350M
  Equity Value = 1500M - 350M = 1150M
  PE 投入: 200M
  PE 退出: 1150M
  MOIC = 1150/200 = 5.75x
  IRR ≈ 42% / 年 (5 年 5.75 倍的年化回报)
```

**关键观察**:
- 公司本身只增长了 1.5 倍(EBITDA 100→150,EV 8x→10x),但 PE 回报是 5.75 倍 — 杠杆 + multiple expansion 共同放大。
- 如果 exit multiple 也是 8x(没扩张):1150M → 950M equity → 4.75x MOIC(只靠杠杆 + EBITDA 增长)。
- 如果 exit EBITDA 只有 120M(没增长):PE 回报约 3x(只靠杠杆 + 还债)。

**实战敏感性**:Real-world LBO 失败通常发生在:
- 收购时 multiple 太高(进入贵了)
- 退出时 multiple 收缩(market downturn)
- 公司去杠杆太快(强制还款导致 capex 不足)
- 行业周期下行(EBITDA 跌到无法 cover 利息)

### 5.6 J-curve / Dry Powder / Preferred Return / Hurdle / Catch-up

**J-Curve (J 型曲线)**:基金早期净回报为负(管理费 + 未实现收益),后期转正形成的 J 形曲线。前几年 LP 看着亏钱别慌。

**Dry Powder (干火药)**:PE 基金已募集但尚未投出去的可投资金。"满仓找不到项目"。

**Waterfall (收益瀑布分配)**:基金退出收益按 **return of capital → pref → catch-up → carry** 顺序分配:

```text
1. Return of Capital:先还 LP 本金
2. Preferred Return:LP 拿到 8% 优先回报(每年 8% 复利)
3. Catch-up:GP 追上自己应得的 20%(LP 拿满 8% 后,GP 把后续收益"追上"到自己应得比例)
4. Carry:剩余的 80% 给 LP,20% 给 GP
```

**Hurdle Rate (门槛收益率)**:LP 开始参与分成前,基金必须先达到的最低回报率(常 8%)。

**Preferred Return (Pref / 优先回报)**:LP 在 GP 分 carry 之前优先获得的最低回报(常 8%)。

**Catch-up (追赶机制)**:GP 在 LP 拿满 pref 后,先把后续收益"追上"到自己应得的比例。

#### 5.6.1 Waterfall 数字算例

假设 LP 投入 $100M,基金 8% pref,GP 20% carry,5 年后退出总收益 $300M(已分配现金):

```text
1. Return of Capital:
   还 LP 本金: 100M
   剩余待分: 200M

2. Preferred Return (8% 复利,5 年):
   LP pref = 100M x (1.08)^5 - 100M = 46.93M
   剩余待分: 200M - 46.93M = 153.07M

3. Catch-up (让 GP 拿到自己应得的 20%):
   GP catch-up = 46.93M / 80 x 20 = 11.73M
   (公式:catch-up 后的剩余按 80/20 分)
   剩余待分: 153.07M - 11.73M = 141.34M

4. Carry Split (80/20):
   LP 拿到: 141.34M x 80% = 113.07M
   GP 拿到: 141.34M x 20% = 28.27M

最终分配:
  LP 拿回: 100M (本金) + 46.93M (pref) + 113.07M (carry split) = 260M
  GP 拿到: 11.73M (catch-up) + 28.27M (carry) = 40M
  验证: 260 + 40 = 300M ✓
  LP 净回报: (260 - 100) / 100 = 1.6x (5 年) = 26% IRR
  GP 净收入: 40M (无本钱) = 0.4x carry on 基金总规模
```

**实战含义**:
- LP 总 MOIC = 2.6x,IRR ≈ 21%(可接受)
- GP 净赚 40M,但要花 5 年时间和人力(假设 2 个 partner + 2 个 associate 五年)
- 如果基金没达到 pref,GP 一分钱 carry 拿不到(只有 management fee)
- Catch-up 让 GP 在 LP 拿满 pref 后能尽快进入"分 20%"状态

## 6. 给富人管钱的 — WM(简要)

**Wealth Management (WM / 财富管理)** 给**高净值客户**(HNW, net worth > $1M)管钱,核心动作:

- **Client Review (客户复盘)** — 定期与客户讨论投资组合表现、调整需求。
- **Financial Plan (财务规划)** — 5-10 年的财务目标规划:退休、教育、买房、税务。
- **Rebalance (再平衡)** — 把组合调回目标配置(例如目标 60% 股 + 40% 债,但股市涨导致变成 70% 股,卖掉一部分股回到 60/40)。
- **TLH (Tax Loss Harvesting / 税收亏损收割)** — 故意卖出亏钱的投资,实现"账面亏损"用来减税,然后买回类似资产(避免错过市场)。
- **Proposal (方案)** — 给客户的资产配置建议文档。
- **Suitability (适当性)** — 监管要求:方案必须与客户的风险承受能力匹配。

**对应 handbook**:`wealth-management` vertical + `meeting-prep-agent` agent。

## 7. 给基金记账的 — Fund Admin + Operations(简要)

### 7.1 GL Reconciliation / Break Trace

**GL (General Ledger / 总账)** 是公司/基金的"会计主账"。

**Reconciliation (对账)**:核对两套账是否一致(例如 GL 总账 vs 子账(subledger))。

**Break (差异)**:对账过程中两边不一致的金额或科目。例如 GL 显示某基金有 100 股,子账显示 80 股 — 差 20 股就是 break。

**Break Trace (差异溯源)**:找出 break 根因(时点错 / 币种错 / 科目错 / 漏记交易)的追溯过程。

**类比**:GL vs 子账对账像银行对账单 vs 你的记账本 — 应该一致,但偶尔有差异(ATM 取款银行已记账你还没记,etc.)。

### 7.2 NAV Package / LP Statement / Capital Account

**NAV (Net Asset Value / 净资产价值)**:基金持有的资产按市值减去负债后的净值。LP 报告的核心数字。

**NAV Package (估值数据包)**:GP 季报周期提交给 LP 的资产估值明细数据包 — 每个 holding 的估值方法、市场参考价、调整项。

**LP Statement (有限合伙人对账单)**:每季度寄给 LP 的对账单:本期 capital call + distribution + NAV + capital account 余额。

**Capital Account (资本账户)**:每个 LP 在基金中的本金 + 损益累计余额明细。

### 7.3 Accrual / Roll-Forward / Variance Commentary

**Accrual (计提)**:期末把已发生未收付的费用/收入入账的会计分录。例如 12 月的水电费 1 月才付,但 12 月要计提。

**Roll-Forward (滚转)**:BS 科目 期初 + 变动 - 反转 = 期末 的桥接分析。例如期初 AR 1000 + 新增 500 - 收回 300 = 期末 1200。

**Variance Commentary (差异说明)**:实际 vs 预算/上期的 P&L/BS 波动解释段落。"为什么这个季度管理费比预算高 10%?"。

### 7.4 Tie-Out / Sign-Off

**Tie-Out (对到一致)**:把两份报告对到完全一致(例如 LP 报表 vs NAV 包 vs GL)。

**Sign-Off (签字放行)**:经过 tie-out + 复核后,签字表示"数字准确,可以对外发布"。

### 7.5 KYC / AML / Screening / Escalations

**KYC (Know Your Customer / 客户身份识别)**:合规流程,验证客户身份、所有权、资金来源。

**AML (Anti-Money Laundering / 反洗钱)**:防止洗钱合规框架,与 KYC 配套。

**Screening (筛查)**:把客户名字与制裁名单、PEP(政治人物)名单做匹配。

**Escalation (升级)**:KYC 命中红线时上报给合规官的流程。

**对应 handbook**:`fund-admin` + `operations` verticals + `gl-reconciler` / `month-end-closer` / `statement-auditor` / `kyc-screener` agents。

### 7.6 PE 投决会的"投票门槛" — 什么样 deal 才能通过

PE 投决会不是凭感觉,有硬性指标(不同基金有差异,但典型):

| 指标 | 典型门槛 | 含义 |
|---|---|---|
| Base Case IRR | ≥ 20% | 中性假设下的年化回报 |
| Downside IRR | ≥ 10% | 悲观假设下仍要赚钱 |
| Base Case MOIC | ≥ 2.5x | 中性假设下 2.5 倍退出 |
| Hold Period | 4-6 年 | 通常 5 年退出 |
| Entry Multiple | 6-8x EBITDA | 买入价不能太贵 |
| Leverage | 4-6x EBITDA | 债务不能太高 |
| Equity Check | < 基金 size 10% | 单笔不能太大 |
| Industry / Geography | 符合基金 thesis | 战略匹配 |
| Mgmt Quality | Sponsor 要信任 | 团队靠谱 |

**实战含义**:一个 deal 即使 50/50 通过率,也要等 IRR / MOIC / 多重敏感性都达标。Partner 看 IC memo 时经常问"downside 是多少?",如果没有靠谱的 downside 假设,memo 直接被退回来重写。

**对应 handbook**:`private-equity/ic-memo` skill 的 9 段结构(§5.4),`valuation-reviewer` agent 输出 IRR/MOIC sensitivity。

### 9.4 术语背后的故事 — 几个有趣的起源

读到这里的读者,送几个"为什么这个术语叫这个名字"的小故事,帮你加深印象:

- **Football Field(估值区间图)**:投行把不同估值方法画在一张图上,横轴是每股价格,每种方法是一个长条状区间。所有长条叠在一起像橄榄球场上的码线(gridiron),所以叫 football field。
- **CIM(Confidential Information Memorandum)**:直译"保密信息备忘录"。原本"卖书"的英文是 selling book 或 offering memorandum,CIM 是 1990 年代才流行的"卖公司专用文档"叫法。
- **Teaser**:早期 IB 给潜在买家匿名发的"一页纸"是字面意义的"tease"(挑逗)— 让买家感兴趣但没足够信息做决定,所以叫 teaser。
- **LBO 的"杠杆"**:Leverage 来自法语 lever(举起),LBO 用债务"撬起"比自己本金大几倍的资产,像杠杆原理。
- **Waterfall(收益瀑布)**:基金分配顺序的英文叫 waterfall,因为收益像瀑布一样**一层一层往下流**(先还本金、再 pref、再 catch-up、再 carry)。
- **J-Curve(J 型曲线)**:基金早期净值为负(因为收了管理费但投资还没退出),后期转正,画出来像字母 J。
- **Carried Interest(Carry)**:GP 跟 LP"carry"(承担)基金的一部分投资风险,因此有资格分享收益。20% 是 1960-70 年代 PE 行业演化出来的标准。
- **Dry Powder(干火药)**:比喻已经准备好但还没发射的弹药 — 钱已募集但没投出去。
- **IOI vs Final Bid**:IOI = Indication of Interest(意向),"我们大致感兴趣,价格 95-105";Final Bid = 正式报价,有法律约束力,不能再反悔。
- **DD Checklist 的起源**:90 年代 PE 行业从 M&A 借鉴来的"标准化尽调清单"。一份完整的 DD checklist 通常 200-500 个问题(财务 / 法律 / 商业 / 运营 / HR / IT / ESG)。
- **Covenant(契约条款)**:这个词来自拉丁语 convenire(同意)。贷款合同里限制借款人的条款,例如"杠杆率不能超过 5x EBITDA"。违反 covenant = technical default = 银行可强制还款。
- **PPA (Purchase Price Allocation)**:把收购对价"分摊"到不同资产项(土地、设备、专利、商誉)。商誉(goodwill) = 收购价超过可辨认净资产公允价值的部分,只在并购时产生。
- **KYC 的起源**:1970 年美国 Bank Secrecy Act 要求银行识别客户,1990 年代扩到所有金融机构。"Know Your Customer" 已成为全球反洗钱合规标准。
- **Fund Accountant 的"独立"角色**:Fund Admin 与 GP(基金管理人)**法律上独立**,确保 LP 拿到的报表不被 GP"美化"。这是 LP 信任基金的关键机制。
