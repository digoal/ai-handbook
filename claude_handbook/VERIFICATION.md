# 事实核验规范

本规范定义手册中的产品事实如何进入正文。目标不是证明每一句教学解释，而是让所有容易随版本变化、容易抄错或容易被误解为产品承诺的内容都可追溯。

---

## 来源优先级

按以下顺序核验：

1. 当前 macOS 上的实际行为与只读命令输出。
2. [Claude Code 官方文档索引](https://code.claude.com/docs/llms.txt)定位到的官方功能页。
3. [Claude Code 官方 changelog](https://code.claude.com/docs/en/changelog)。
4. 官方 `anthropics/claude-code` 仓库中的发布说明。

现有 01–10 课程、第三方文章、搜索摘要和 AI 回答只能提供待核验线索，不能单独支撑课程事实。

## 证据等级

### 已实测

同时满足以下条件：

- 在 [SOURCES.md](SOURCES.md) 中记录 Claude Code 版本、macOS 版本和日期。
- 保存了不含敏感信息的命令输出，或写明了可重复的观察步骤。
- 实际结果与课程表述一致。

### 官方核对

官方文档或 changelog 明确说明，但本机没有执行对应行为。安装、升级、登录、订阅专属功能和可能产生费用的操作通常属于此类。

### 条件性

事实只在特定订阅、认证方式、安装渠道、feature gate 或组织策略下成立。正文必须紧邻说明条件，不能把它泛化为所有用户的默认行为。

### 待验证

尚无足够证据。可以保留在章节的“待核验问题”中，但不能作为已发布正文中的确定结论。

## 必须登记的声明

以下内容必须在 [SOURCES.md](SOURCES.md) 中拥有稳定事实 ID：

- 命令、subcommand、flag、参数和可选值
- 默认值、优先级和覆盖关系
- 配置文件路径、作用域与加载顺序
- 权限模式、hook 事件、输入输出字段等枚举
- 数量、上限、超时和版本要求
- 模型、订阅、认证、平台或 feature gate 差异
- “从某版本开始”“已弃用”“自动执行”等生命周期声明

概念解释和教学建议不必逐句编号，但不得与已登记事实冲突。

## 核验流程

### 1. 锁定基线

在写作开始和发布前分别运行：

```bash
claude --version
sw_vers
```

若 Claude Code 版本在写作期间发生变化，先停止发布，重新检查受影响的命令和页面。

### 2. 采集本机证据

只采集与当前章节直接相关、不会改变系统状态的输出：

```bash
claude --help
claude auth --help
claude doctor --help
claude install --help
claude update --help
```

输出保存在 `evidence/<version>/`。不要把“help 中存在”扩大解释成“所有账户都可使用”或“未来版本保证兼容”。

### 3. 核对官方资料

先打开官方 `llms.txt` 索引，再定位到具体功能页。每条来源记录：

- 页面标题和稳定 URL
- 核验日期
- 它支持的具体声明
- 是否存在版本、平台、订阅或安装渠道条件

不要只验证 URL 能访问；必须阅读实际内容。

### 4. 登记事实

在 [SOURCES.md](SOURCES.md) 新增稳定 ID。一个 ID 只表达一个可清楚判断真假的声明，避免把多个独立行为塞进同一条。

### 5. 写入课程

课程中的版本敏感句子链接到事实 ID。若来源仅为“官方核对”，正文不得写成“我们已经在本机完成了该操作”。

### 6. 发布前复核

逐条检查：

- 课程表述是否比证据更宽泛。
- 命令拼写和大小写是否与本机 help 一致。
- 条件是否紧邻结论。
- 同一事实是否被复制到多个章节并发生漂移。
- 待验证内容是否误入正文。

## 安全与脱敏

禁止提交：

- `~/.claude/settings.json` 或其他真实用户配置
- API key、OAuth token、cookie 或 Keychain 内容
- debug 日志、会话 transcript 或 prompt history
- 用户名、主目录绝对路径、私有仓库名或组织信息
- 可能包含凭证的环境变量输出

配置示例必须使用虚构值或干净的临时练习目录。不得为了核验文档自动执行安装、升级、登录、发布、删除或会产生 API 费用的命令。

## 写作规则

- 复用仓库根目录 [STYLE_GUIDE.md](../STYLE_GUIDE.md) 的命名、标题、表格、相对链接、代码 fence 和 callout 规则。
- 每章只保留一个 H1，标题不跳级。
- 所有代码 fence 都声明语言；纯输出使用 `text`。
- Mermaid 只在能解释流程时使用，并在图后补充文字说明。
- 示例优先短小、可复制、可观察；不以“生产级”包装未经真实使用的模板。
- 易变长表只保留一个权威位置，其他章节链接过去。
