CONTEXT IS NOT POLICY控制

Instructions 决定“应该怎么做”，Permissions 决定“能不能做”

自然语言规则能引导行为，但不能替代硬性授权边界。

CLAUDE.md / Instructions

1
多作用域并存

managed、user、project、local 都可提供 instructions，不把它们当成 permission 覆盖链。

2
目录层级追加

父目录到工作目录追加加载；子目录 instructions 在访问对应文件时按需进入 Context。

3
Import 仍占 Context

@path 最多递归 4 hops；拆文件不等于省 token。

CONFIG PRECEDENCE ≠ PERMISSION OVERRIDE控制

普通 Settings 有优先级；Permission rules 走“更严格合并”

1Managed组织管理员强制策略
2CLI当前启动参数
3Local当前项目的个人配置
4Project团队共享配置
5User个人跨项目偏好

Permission 是例外

跨 scope 的 allow / ask / deny 会合并，并按更严格结果执行。Local allow 不会覆盖 managed/project deny。

  1. 先 deny 明确禁止项
  2. 不确定操作保持 ask
  3. 仅为稳定、最小前缀增加 allow

DEFENSE IN DEPTH控制

“允许工具调用”不是一个布尔开关

五层边界互补：任何一层都不应被误解为“批准所有操作”。

01

Workspace trust

确认代码库与项目级授权来源；不等于批准所有 tool calls。

02

Permission mode

决定交互策略与可用行为；账户/模型/策略可能影响某些模式。

03

Rules

Allow / ask / deny 按 matcher 与 scope 合并，取更严格结果。

04

Protected paths

Settings、VCS 元数据与 shell 启动文件仍需额外确认。

05

Sandbox

对 Bash 提供 OS 级 filesystem/network 隔离；不控制所有工具。

!
条件性

2.1.214 的 help 列出 6 个 permission mode；其中 auto 受账户、模型、provider 和组织策略影响。本手册不使用 bypassPermissions。

THE SLASH IS AN ENTRY, NOT AN IMPLEMENTATION扩展

看到 /，不要先猜它背后的实现

Slash command 是入口表面；它可能来自 CLI built-in、bundled skill、workflow 或自定义 Skill。

/

Built-in command

  • 由 CLI 直接实现
  • 负责会话控制、配置界面等
  • 清单随版本和环境变化
S

Skill

  • SKILL.md 定义可复用 instructions
  • 正文按需加载
  • 可显式调用，也可按 description 相关性选择
P

Plugin

  • 分发 skills、agents、hooks、MCP
  • 不是单一命令格式
  • 引入新的供应链边界
!
Custom commands 已合并到 Skills

旧 .claude/commands/*.md 仍可工作；新内容统一使用 .claude/skills/<name>/SKILL.md，避免双份维护。

FAST REWIND ≠ VERSION CONTROL控制

Checkpoint 管“刚才”，Git 管“长期”

Checkpoint

会话级、低摩擦、贴近 prompt

  • 每个 user prompt 前自动创建
  • 跟踪 Claude 编辑工具修改
  • 可恢复 code / conversation / 两者
  • 随 session 保存
  • 不跟踪 Bash、手工编辑、并发 session
  • 不是文件系统快照
VS

Git

长期、可审查、可协作

  • 记录明确提交与分支
  • 跨 session、跨成员共享历史
  • 可独立检查 working tree / index
  • 承担发布与合并基线
  • 不会恢复 conversation
  • 不替你决定 prompt 分支
↺
组合方式

先建立 Git baseline，再用 checkpoint 做近场试错；需要永久保留时创建 commit，而不是依赖 session checkpoint。

DIAGNOSE BEFORE DELETING STATE运维

先缩小变量，最后才删除状态

排障的核心不是“多跑几个命令”，而是每次只关闭一类 customization，保留可比较基线。

STEP 1Version + doctor记录版本与 cwd；运行只读 doctor。
STEP 2Minimal repro在最小目录确认问题是否仍存在。
STEP 3Safe mode排除 CLAUDE.md、skills、plugins、hooks、MCP 等 customizations。
STEP 4Bare mode再跳过 auto-memory、background prefetch、keychain reads 等层。
STEP 5Debug / dry-run临时日志先脱敏；删除前先 project purge --dry-run。
×
Safe mode 与 Bare mode 不是强弱别名

它们跳过的层和认证边界不同；debug logs、transcripts 与 project state 可能包含路径、代码或凭证。

AN ADOPTION MODEL, NOT A PRODUCT TIER运维

建议采用路径：先可观察，再可复用，最后可并行

以下是基于 handbook 的教学模型，不是 Claude Code 官方产品分级。

L1可观察会话Manual / Plan；目标、范围、禁止项与验收清楚。
L2项目约定CLAUDE.md、最小 settings、Git baseline。
L3可复用能力Skills 封装重复流程；Hooks 只做可独立测试的门禁。
L4受控集成MCP / Plugins：明确 scope、认证、供应链与回退。
L5可审计自动化Headless / workflows：输入、工具、预算、依赖、停止、汇总。
Workflow 条件见 CC-079

格式适合Consumer 责任关键边界

Session

Budget

Fallback
