# §40 频道、关卡、审批

> 🏛️ 架构师 · 👤 用户 · 🧑‍💻 开发者
>
> **一句话定位**:Channel 是协调面、Barrier 是等待点、Approval 是治理门 — 三者共同支撑 Agent 间协作与流程门控。

---

## 1. 三者对比

```mermaid
flowchart LR
    A["Channel<br/>协调面"] -->|"消息/动作"| B["成员"]
    C["Barrier<br/>等待点"] -->|"release"| D["胜出者"]
    E["Approval<br/>治理门"] -->|"N-of-M 通过"| F["决策"]
    style A fill:#9f9
    style C fill:#ff9
    style E fill:#f99
```

| 维度 | Channel | Barrier | Approval |
|---|---|---|---|
| **角色** | 协调/消息 | 同步等待 | 治理决策 |
| **作用对象** | 成员(人类+Agent) | 参与者 | 审批者 |
| **生命周期** | 持久 | 单次 | 单次 |
| **门控** | ❌ | ✅ 唯一胜出 | ✅ 多人通过 |
| **可重入** | ✅ | ❌ | ❌ |

## 2. Channel

来源:[`scripts/deploy/16_v4_3_0_identity_channels.sql`](../../scripts/deploy/16_v4_3_0_identity_channels.sql)

### 2.1 模型

```mermaid
erDiagram
    CX_CHANNELS ||--o{ CX_CHANNEL_MEMBERS : "has"
    CX_CHANNELS ||--o{ CX_CHANNEL_MESSAGES : "messages"
    CX_CHANNELS ||--o{ CX_CHANNEL_THREADS : "threads"
    CX_CHANNELS ||--o{ CX_BRIDGES : "cross-domain"

    CX_CHANNELS {
        string channel_id PK
        string channel_name
        string channel_type "DIRECT/GROUP/PUBLIC"
        string status "ACTIVE/ARCHIVED/LEGAL_HOLD"
        string created_by
        timestamp created_at
    }
    CX_CHANNEL_MEMBERS {
        string member_id PK
        string channel_id FK
        string principal_id FK
        string role "OWNER/MEMBER"
        timestamp joined_at
    }
    CX_CHANNEL_MESSAGES {
        string message_id PK
        string channel_id FK
        string sender_principal_id
        text content
        json metadata
        timestamp created_at
        string delivery_status
    }
```

### 2.2 Channel 操作

| 操作 | 用途 |
|---|---|
| `create_channel` | 创建 |
| `add_member` | 加成员 |
| `send_message` | 发消息 |
| `get_messages` | 读消息 |
| `mark_read` | 标记已读 |
| `create_thread` | 创建主题 |
| `archive_channel` | 归档 |
| `legal_hold` | 法律保留 ⚠️企业版 |

### 2.3 关键不变量

> Channel 是**协调面**,**不是权限放大器**:
> - 加入 Channel 不授予数据库行
> - 不授予 API、Skill、Tool、Memory、Artifact、Export
> - 跨域传输需要 explicit Bridge 策略

```mermaid
flowchart LR
    A["Channel 成员"] --> B["Database 行"] -.->|❌ 不授予| A
    A --> C["API"] -.->|❌ 不授予| A
    A --> D["Skill/Tool"] -.->|❌ 不授予| A
    style B fill:#fcc
    style C fill:#fcc
    style D fill:#fcc
```

### 2.4 创建 Channel

```python
from lib import message_api

ch = message_api.create_channel(
    channel_name="Project Alpha",
    channel_type="GROUP",
    initial_members=["agent_a", "agent_b", "user_x"]
)
```

## 3. Action Card

来源:[`16_v4_3_0_identity_channels.sql`](../../scripts/deploy/16_v4_3_0_identity_channels.sql) - `cx_action_cards`

### 3.1 用途

Action Card 是 Channel 内可执行的"动作卡片" — 成员可点击触发:

```python
action_api.create_action_card(
    channel_id="CH_xxx",
    title="批准部署",
    action_type="deployment_approve",
    action_data={"deployment_id": "DEP_yyy"},
    require_approval=True
)
```

| 字段 | 含义 |
|---|---|
| `action_id` | 唯一 |
| `action_type` | 类型(部署/审批/查询) |
| `action_data` | 参数 |
| `require_approval` | 是否需审批 |

## 4. Bridge(跨域通道)

### 4.1 用途

Bridge 是 Channel 之间的**有策略通道**,用于跨域传递消息:

```mermaid
flowchart LR
    A["Channel A<br/>(domain X)"] -->|Bridge 策略| B["Channel B<br/>(domain Y)"]
    style A fill:#ffd
    style B fill:#ffd
```

### 4.2 Bridge 配置

| 字段 | 含义 |
|---|---|
| `bridge_id` | 唯一 |
| `source_channel_id` | 源 |
| `target_channel_id` | 目标 |
| `classification_check` | 是否检查分类 |
| `redaction_policy` | 脱敏策略 |
| `audit_required` | 是否强制审计 |

### 4.3 Bridge 转移

```python
    bridge_id="BR_xxx",
    payload={"...": "..."}

```

## 5. Barrier(关卡)

来源:[`16_v4_3_0_identity_channels.sql`](../../scripts/deploy/16_v4_3_0_identity_channels.sql) - `cx_barriers`

### 5.1 模型

```mermaid
erDiagram
    CX_BARRIERS ||--o{ CX_BARRIER_REPORTS : "arrivals"
    CX_BARRIERS ||--|| CX_BARRIERS : "winner"

    CX_BARRIERS {
        string barrier_id PK
        string workspace_id FK
        string graph_run_id FK
        string name
        json participant_snapshot
        json role_requirements
        string status "WAITING/READY/COMMITTED/CANCELLED/DEADLOCKED"
        string winner_id
        timestamp created_at
        timestamp released_at
    }
    CX_BARRIER_REPORTS {
        string report_id PK
        string barrier_id FK
        string principal_id FK
        json payload
        string idempotency_key
        timestamp arrived_at
    }
```

### 5.2 关键不变量

- 等待的 Agent **不**持有 Worker Lease
- **一人胜出**(one-winner)
- 不可变参与快照(participant_snapshot)
- 不可变角色要求(role_requirements)
- 幂等证据(idempotency_key)
- Gateway 对 instance_token 做围栏
- **只释放本节点 instance**(不撤销其他节点)

### 5.3 Barrier 流程

```mermaid
sequenceDiagram
    participant A1 as Agent 1
    participant A2 as Agent 2
    participant A3 as Agent 3
    participant B as Barrier
    participant DB

    Note over B: 创建 Barrier(3 participants required)
    A1->>B: arrive(payload1)
    A2->>B: arrive(payload2)
    A3->>B: arrive(payload3)
    B->>DB: 验证角色要求
    B->>DB: 检查 idempotency
    alt 全部到位
        B->>DB: 选择 winner(基于角色/优先级)
        B-->>A1: LOSER
        B-->>A2: LOSER
        B-->>A3: WINNER + released_payload
    else 超时
        B->>DB: status=CANCELLED
    end
```

### 5.4 Barrier vs Lock

| 维度 | Barrier | 分布式锁 |
|---|---|---|
| 一次性 | ✅ | ❌(可重入) |
| 角色约束 | ✅ | ❌ |
| 参与快照 | ✅ | ❌ |
| 胜出者明确 | ✅ | ❌ |

## 6. Approval(审批)

来源:[`docs/security.md`](../security.md) + Enterprise 治理

### 6.1 N-of-M Approval 模型

```mermaid
stateDiagram-v2
    [*] --> Pending: create_approval
    Pending --> Approved: 收到 N 个 ALLOW
    Pending --> Denied: 收到 N 个 DENY
    Pending --> Expired: 超时
    Approved --> [*]
    Denied --> [*]
    Expired --> [*]
```

### 6.2 关键不变量

- **决策归属于认证 Principal**(不接受 `approver_id` from body)
- **默认排除 Requester**
- **职责分离**(角色/组分离规则)
- **Append-only**(决策不可改)
- **幂等**(重复决策返回 `ALREADY_TERMINAL`)

### 6.3 审批操作

```bash
# 创建审批
POST /api/governance/approvals
{
  "decision_target": "deployment_xyz",
  "required_count": 2,
  "candidate_approvers": ["role:admin"],
  "reason": "生产部署需要审批"
}

# 提交决策
POST /api/governance/approvals/{id}/decision
{
  "decision": "ALLOW",
  "comment": "已检查,风险可接受"
}
```

### 6.4 审批状态查询

```bash
GET /api/governance/approvals
# 返回:
{
  "approvals": [
    {
      "approval_id": "APPR_xxx",
      "status": "OPEN",
      "required_count": 2,
      "decisions": [
        {"approver": "user_a", "decision": "ALLOW", "at": "..."}
      ]
    }
  ]
}
```

## 9. 故障排查

| 问题 | 排查 |
|---|---|
| Channel 消息 403 | 检查 Principal 是否在 Channel 内 |
| Barrier 永远不释放 | 检查 required_count 和 arrivals |
| Approval 一直 OPEN | 检查 approvers 列表与角色 |
| Bridge 转移失败 | 检查 classification_check |
